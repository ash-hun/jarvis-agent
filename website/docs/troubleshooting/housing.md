# 청약 공고 조회

KAREN 의 청약 도구가 오류를 돌려주거나, 도구를 부르지 않고 답하거나, 계산 결과가 이상하다. 도구는 공고를 지어내지 않고 오류를 그대로 돌려주므로, 오류 문구와 도구 실행 줄로 원인을 가른다.

## 확인 순서

1. KAREN 의 답이나 도구 결과에 `LH 게시판 조회 실패`, `SH 게시판 조회 실패`, `예상한 목록 표를 주지 않았다`, `공고 상세를 읽지 못했다` 가 있는지 본다.
2. 게시판 조회 실패라면 백엔드 컨테이너에서 `curl -I https://apply.lh.or.kr` 로 연결을 확인한다.
3. HUD 의 도구 실행 줄에서 어떤 도구(`lh_notice`, `housing_budget`, `housing_loan` 등)가 불렸는지 본다.
4. JARVIS 세션에서 물었다면 TOOLS 목록에 청약 도구가 없는 것이 맞는지 확인한다.

## 원인과 해결

- `LH 게시판 조회 실패` 나 `SH 게시판 조회 실패`: 사이트에 연결하지 못했거나 오류 응답을 받은 것이다. 백엔드 컨테이너에서 `curl -I https://apply.lh.or.kr` 로 연결을 확인한다
- `예상한 목록 표를 주지 않았다`, `공고 상세를 읽지 못했다`: 사이트 화면 구조가 바뀌었거나, 점검 화면이나 접속 대기(NetFunnel) 화면이 뜬 것이다. 도구는 공고를 지어내지 않고 이 오류를 돌려준다. 계속되면 `core/tools/housing/` 의 파싱 정규식을 실제 페이지에 맞춘다
- JARVIS 에게 도구가 없음: 청약 도구는 KAREN 전용이므로 JARVIS 세션의 TOOLS 에 보이지 않는 것이 맞다. 다른 에이전트에게 주려면 그 정의 파일의 `tools` 에 이름을 적는다
- 도구를 부르지 않고 지난 공고로 답함: 작은 모델이 KAREN 의 장기 기억(지난 턴 일화)을 꺼내 답한 경우다. 프롬프트는 매번 도구를 먼저 부르게 하지만, 그래도 계속되면 "lh_notice 로 다시 조회해" 처럼 도구 이름을 말하거나 더 큰 모델을 쓴다
- 예산 추천에 "금액을 찾지 못한 공고" 가 많음: 매입임대, 전세임대는 집마다 금액이 달라서 금액이 주택목록 엑셀에만 있다. 임대 공고는 공고문 PDF 의 임대조건 표를 읽는데, 표가 표준 꼴이 아니면 읽지 못한다. 결과의 링크로 첨부를 직접 확인한다
- 예산 추천의 가장 싼 주택형이 내 자격과 다름: 주택형 이름에 붙은 공급대상(수급자, 청년, 「가」군 등)이 신청 자격이다. 도구는 조건에 맞는 주택형 중 월 부담이 가장 작은 것을 고른다
- 상환액이 이상함: 답에 `housing_loan` 결과의 숫자가 그대로 있는지 본다. 모델이 손으로 계산한 값이면 틀릴 수 있다. HUD 의 도구 실행 줄에서 `housing_loan` 이 불렸는지 확인한다

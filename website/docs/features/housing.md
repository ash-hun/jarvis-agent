# 청약 공고와 대출 계산

KAREN 은 LH, SH 청약 공고를 직접 조회하고, 공고의 분양가나 보증금으로 대출 상환액을 계산한다. 도구 세 개가 `core/tools/housing/` 에 있다. JARVIS 는 이 도구를 갖지 않고, 청약 질문을 받으면 `ask_agent` 로 KAREN 에게 맡긴다.

| 도구 | 하는 일 | 출처 |
|---|---|---|
| `lh_notice` | LH 임대, 분양, 주거복지(매입/전세임대), 신혼희망타운, 토지, 상가 공고를 지역, 상태, 유형, 키워드로 조회하고 KST 기준 마감을 붙인다. `id` 를 주면 상세 | LH 청약플러스 `apply.lh.or.kr` 공개 게시판 |
| `sh_notice` | SH 공고 및 공지 게시판을 키워드, 공고 종류로 조회한다. `seq` 를 주면 본문, 담당부서, 첨부 이름과 크기, 미리보기 링크 | SH `www.i-sh.co.kr` 공개 게시판 |
| `housing_loan` | 원리금균등, 원금균등, 만기일시의 월, 연간 상환액과 총이자. 거치기간, 분양가와 LTV 또는 자기자금으로 원금 정하기, 월 상환액에서 금리 역산. LH 공고 id 와 주택형을 주면 그 공고의 분양가나 보증금을 직접 읽는다 | 계산. `notice_id` 를 주면 LH 공고 상세 |

셋 다 읽기와 계산만 한다. 로그인, 청약 신청, 파일 내려받기는 하지 않으므로 승인 없이 돈다.

## 어떻게 가져오나

데이터를 가져오는 방식은 [k-skill](https://github.com/NomaDamas/k-skill) 의 `lh-notice-search`, `sh-notice-search` 를 참고했다. 스킬이나 그 프록시를 쓰지 않고, 같은 공개 출처를 우리 도구가 직접 읽는다.

- **LH**: k-skill 은 공공데이터포털 LH 공고 API 를 자기 프록시(서비스키 보관)로 부른다. 여기서는 서비스키 없이 열리는 청약플러스 공고문 게시판을 읽는다. 게시판 검색 폼과 같은 값(메뉴, 유형 코드, 지역 코드, 상태, 기간, 공고명)을 보내고 목록 표와 상세 페이지를 푼다
  - 기간은 기본으로 게시일 최근 1년이다. 게시판 기본값(2개월)이면 연초에 올라와 연말까지 열린 수시모집 공고가 빠진다
  - `closing_within_days` 를 주면 게시판의 마감일 기간 검색으로 바꿔 오늘부터 n일 안에 마감하는 공고만 받는다
  - 상세는 공고 상태, 공고일, 마감일, 공고문 파일 이름, 주택형 표(세대수, 임대보증금과 월임대료 또는 평균분양가격), 공급정보, 공급일정, 접수처를 준다
- **SH**: k-skill 과 같이 공개 HTML 게시판을 직접 읽는다. 검색어를 보낼 때 `srchTp`(제목 0, 본문 1)를 꼭 붙인다. 없으면 게시판이 검색어를 무시한다. 한 쪽은 10건 고정이라 더 보려면 `page` 를 넘긴다. 첨부는 페이지 스크립트의 `downList` 가 정본이고, 주석 속 확장자 아이콘 견본은 첨부가 아니다

## 마감 표시

마감은 KST 오늘과 마감일을 비교해 붙인다(`markup.deadline_label`). 서버 시간대와 상관없다.

| 경우 | 표시 |
|---|---|
| 마감일이 지남 | `마감됨` |
| 마감일이 오늘 | `오늘 마감` |
| n일 남음 | `D-n` |
| 마감일이 없음(토지, 상가의 상담요청 등) | `마감일 없음` |

LH 상태 값 `공고중` 은 게시판에서 `접수중`, `정정공고중` 까지 함께 보여준다. SH 게시판에는 상태 칸이 없어 제목 말로 짐작한다(`모집/접수`, `마감/결과`, `당첨/발표`). 도구 결과에 짐작한 값이라고 적는다.

## 인자

`lh_notice`

| 인자 | 값 |
|---|---|
| `category` | `임대`, `주거복지`, `신혼희망타운`, `분양`, `토지`, `상가`. 비우면 임대와 분양을 함께 |
| `subtype` | `행복주택`, `국민임대`, `영구임대`, `매입임대`, `전세임대`, `공공분양(신혼희망)` 등. 주면 category 는 따라 정해진다 |
| `region` | `서울`, `경기`, `충북`, `부산광역시` 처럼 줄여도 된다. 비우면 전국 |
| `status` | `공고중`, `접수중`, `접수마감`, `정정공고중`, `상담요청` |
| `keyword` | 공고명에 든 말 |
| `closing_within_days` | 오늘부터 n일 안 마감 |
| `limit` | 기본 10, 최대 50 |
| `id` | 목록 결과의 id(`공고ID-시스템-대분류-세부`). 주면 상세 |

`sh_notice` 는 `category`(`임대` 기본, `분양`, `주거복지`, `입주`, `토지`, `상가`, `보상`, `기타`, `전체`), `keyword`, `search_in`(`제목`, `본문`), `status`, `page`, `seq`. `주거복지` 는 SH 공개 게시판의 `주택매입` 분류로 찾고 결과에 그렇게 적는다.

`housing_loan` 은 `years`(필수)와 금리(`annual_rate_percent`) 또는 월 상환액(`monthly_payment`)을 받는다. 원금은 `principal`, 또는 `price` 와 `ltv_percent` 나 `down_payment`. 금리 역산은 거치 없는 원리금균등만 된다.

`notice_id`(lh_notice 의 id)와 `unit`(주택형)을 주면 그 공고 상세의 주택형 표에서 금액을 읽어 `price` 로 쓴다. 분양가 칸이 있으면 분양가, 없으면 임대보증금이다. `55A` 는 `55.9000A` 처럼 면적 정수부와 끝 글자로 맞춘다. 실서버에서 작은 모델(gemma4:e4b)이 상세 조회 뒤 계산 도구를 부르지 않고 손으로 계산해 틀리는 것을 보고, 한 번의 호출로 끝나게 했다.

```text
대출원금 353,138,800원(약 3억 5,314만원) (인천계양 A17블록 신혼희망타운(공공분양) 입주자모집공고 55.9000A 평균분양가격(원) 504,484,000원(약 5억 448만원) × LTV 70%)
금리 연 3.5%, 기간 30년, 원리금균등
월 상환액 1,585,751원(약 159만원) (매달 같음)
1년차 연간 상환액 19,029,012원(약 1,903만원)
```

## 에이전트만 쓰는 도구

이 도구들은 앱 레지스트리가 아니라 `AppContext.agent_tools` 에 들어간다. 정의의 `tools` 에 이름을 적은 에이전트만 받는다. JARVIS 처럼 `tools` 가 빈 에이전트는 앱 레지스트리 전체를 쓰므로 이 도구가 보이지 않는다. 다른 에이전트에게 주려면 그 정의 파일의 `tools` 에 이름을 더한다.

## 한계

- 두 게시판의 HTML 이 바뀌면 파싱이 깨진다. 목록 표나 상세 표를 못 찾으면 도구는 지어내지 않고 오류 결과를 돌려준다
- LH 목록은 첫 쪽(최대 100건)만 읽는다. 게시판의 쪽 넘김은 검색 조건을 잃어서다. 조건을 좁혀 찾는다
- 대출 계산은 고정금리 가정이다. 금리 변동, 중도상환, 보증료, DSR 한도는 반영하지 않는다
- GH, iH 같은 다른 지방 공사 공고는 다루지 않는다

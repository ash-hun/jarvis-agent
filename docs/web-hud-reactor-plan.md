# Web HUD 리액터 중심 UI 개편 계획

Web HUD(`src/jarvis/ui/web/static/`)를 아크 리액터가 화면 중앙을 차지하는 레이아웃으로 바꾸기 위한 점검 결과와 작업 계획이다. 목표 이미지는 화면 가운데 큰 리액터, 그 아래 한 줄 문구, 좌우에 떠 있는 반투명 HUD 카드로 구성된다.

---

## 현재 상태와 목표의 차이

| 항목 | 현재 | 목표 |
|---|---|---|
| 화면 중심 | 채팅창이 가운데를 차지함 | 아크 리액터가 화면 한가운데 크게 배치됨 |
| 리액터 크기 | footer에 붙은 140px ([styles.css](../src/jarvis/ui/web/static/styles.css) `.sphere-wrap`) | 화면 높이의 절반 정도 |
| 리액터 모양 | 쉴 때는 눈금 60개짜리 로고, 작업 중에는 점 900개로 된 구체 ([hud.js](../src/jarvis/ui/web/static/hud.js)) | 두꺼운 바깥 링 안에 여러 겹의 방사형 막대가 있고, 안쪽에는 파랑·보라·분홍 성운 입자가 있음 |
| 주변 패널 | 왼쪽 사이드바에 세션/도구/사용량이 고정됨 | 떠 있는 반투명 HUD 카드가 좌우에 흩어져 있음(할 일 목록, 상태 로그, 신호 분석) |
| 하단 | footer에 통계 표시 | 리액터 아래에 명언이나 에이전트 한 줄 메시지가 가운데 정렬됨 |

### 그 밖의 점검 사항

- 사이드바 TOOLS 목록(`bash / read_file / tts.kr`)이 [index.html](../src/jarvis/ui/web/static/index.html)에 하드코딩되어 있어 실제 도구 목록과 연결되어 있지 않다.
- `LOG / TRACE` 탭은 마크업만 있고 동작은 확인하지 못했다. 구현이 없는 것으로 보인다.
- 색은 `:root` CSS 변수로 관리되고 `hud.js`도 같은 변수를 읽으므로 테마를 확장하기 쉽다.

---

## 작업 계획

### 1단계 — 레이아웃 재구성 (`index.html`, `styles.css`)

- 채팅을 오른쪽 패널로 옮기거나 접히는 오버레이로 바꾸고, `.stage` 가운데를 리액터 자리로 비운다.
- `.sphere-wrap`을 footer에서 빼서 stage 중앙에 두고, `min(52vh, 52vw)` 크기로 키운다.
- 리액터 아래에 `#reactor-caption`(명언 또는 에이전트의 마지막 한 줄)을 추가한다.
- 사이드바를 떠 있는 카드 형태(`.hud-card`: 반투명 배경, 얇은 테두리, 모서리 브래킷)로 바꾼다.

### 2단계 — 리액터 다시 그리기 (`hud.js`)

- 바깥 링: 두께 있는 원 1개와 방사형 막대 링 2~3겹을 겹친다. 링마다 회전 방향과 속도를 다르게 한다.
- 안쪽 코어: 지금의 900개 점 구체를 여러 색 입자와 가산 합성(`globalCompositeOperation = 'lighter'`)으로 바꿔 성운처럼 보이게 한다.
- 기존 상태 연결(`HUD.setState`: `idle` / `thinking` / `tool_running` / `listening` / `speaking` / `error`)은 유지하고, 상태별로 회전 속도, 밝기, 입자 크기만 달라지게 한다.
- 캔버스가 커지므로 DPR 2 기준 성능을 확인한다(입자 수를 줄이거나 오프스크린 캐시 사용).

### 3단계 — 떠 있는 패널에 실제 데이터 연결 (`app.js`)

- 왼쪽 위 **할 일 / open loops**: 이미 있는 `openloop`, `schedule` 슬래시 명령 데이터를 활용한다.
- 오른쪽 위 **활동 로그**: 도구 실행과 proactive 이벤트를 흘려서 표시한다(`LOG` 탭 역할을 흡수).
- 오른쪽 아래 **시스템 상태**: 모델, 토큰, 비용, 가동 시간(지금의 footer와 USAGE 데이터를 재사용).
- TOOLS 목록은 서버가 보내는 실제 도구 목록으로 바꾼다.

### 4단계 — 반응형과 마무리

- 모바일(≤768px): 리액터를 위로 작게 줄이고, 카드는 세로로 쌓이는 드로어로 바꾼다.
- `prefers-reduced-motion` 설정을 유지한다.
- `?v=` 캐시 버전 번호와 `sw.js` 캐시 키를 올려서 PWA에 예전 파일이 남지 않게 한다.

---

## 결정이 필요한 사항

1. **채팅 위치**: 오른쪽 고정 패널로 할지, 평소에는 숨기고 입력할 때만 나오는 오버레이로 할지 정해야 한다. 리액터가 주인공이 되려면 오버레이를 추천한다.
2. **리액터 아래 문구**: 명언을 돌아가며 보여줄지, 에이전트의 마지막 응답이나 proactive 메시지 한 줄을 보여줄지 정해야 한다.

## 진행 방식

- 새 브랜치(예: `feat/web-hud-reactor`)에서 작업한다.
- 1 → 2 → 3 → 4단계 순서로 단계마다 커밋한다.

# Mode

Web HUD 는 두 축의 모드를 따로 고른다. 하나는 말로 주고받는 방식이고, 다른 하나는 화면과 에이전트가 무엇에 집중하는지다. 두 축은 겹쳐 쓸 수 있어서, Full-voice 로 Focus 작업을 해도 된다.

## 서비스 기능

### 풀려는 문제

같은 사용자라도 상황마다 원하는 방식이 다르다. 책상 앞에서는 답을 화면으로 읽는 편이 빠르고, 손이 바쁠 때는 말로 묻고 들어야 한다. 긴 작업 하나에 매달릴 때는 대화 목록보다 분석, 조사, 기록, 진행률이 한 화면에 보이는 편이 낫다. 이 둘을 한 스위치로 묶으면 "말로 하면서 작업에 집중" 하는 조합을 고를 수 없다.

### 무엇을 하나

| 축 | 모드 | 켜는 법 | 무엇이 바뀌나 |
|---|---|---|---|
| 음성 | Default | 헤더 `DEFAULT` | 응답은 화면으로 본다. 구체를 눌러 말한 요청만 읽어 준다 |
| 음성 | Full-voice | 헤더 `FULL-VOICE` | 응답, 승인 요청, 먼저 건네는 말을 읽고 답을 듣는다. 자세한 동작은 [Voice Interface](../conversation/voice.md#full-voice) |
| 작업 | Focus | `/focus <작업>`, 음성 `포커스 모드 <작업>` | 작업 하나에 sub-agent 넷을 붙이고 화면을 네 영역으로 바꾼다. [Focus Mode](./focus-mode.md) |

### 핵심 결과

- Focus 는 첫 분석과 단계 계획을 기다린 뒤 응답하므로 첫 응답까지 로컬 모델에서 약 20초, 클라우드에서 약 3초가 걸린다
- 실제 전사 기록 다섯 번에서 Focus 종료 말은 키워드 해석을 고친 뒤 두 번 모두 명령으로 잡혔다("동요", "종료")

## 세부 구현

### 하위 페이지

| 페이지 | 다루는 것 |
|---|---|
| [Focus Mode](./focus-mode.md) | sub-agent 넷(분석, 조사, 기록, 진행), 턴 훅, 화면 네 영역, 기록 파일과 재시작 복구 |
| [Voice Interface → Full-voice](../conversation/voice.md#full-voice) | 응답, 승인 요청, 먼저 건네는 말을 읽고 답을 듣는 음성 루프 |

### 같이 쓸 때

- Focus 중에도 음성 모드는 헤더에서 그대로 바꾼다. 헤더의 `FOCUS` 표시는 음성 모드와 따로 붙는다
- 음성으로 시작한 요청이면 Default 에서도 승인을 음성으로 묻는다. Focus 중이어도 같다
- Focus 를 끝내도 음성 모드는 바뀌지 않는다

## 성능 비교실험

하위 페이지 실험의 핵심 숫자다. 조건과 해석은 각 페이지에 있다.

| 실험 | 핵심 숫자 | 페이지 |
|---|---|---|
| Focus 첫 응답 시간 | `/focus` 부터 첫 응답까지 gemma4:e4b 19.47~20.08초, gpt-4o-mini 2.77~2.89초 | [Focus Mode](./focus-mode.md#첫-응답-시간과-조사-형식) |
| Focus 조사 형식 | 선례 3개 이하: gemma4:e4b 2/4, gpt-4o-mini 4/4. 번호 목록 없음: 두 모델 모두 4/4 | [Focus Mode](./focus-mode.md#첫-응답-시간과-조사-형식) |
| 음성 Focus 키워드 해석 | 종료 시도 2번: 고치기 전 모두 대화로 갔고, 고친 뒤 2번 모두 `/focus stop`. 시작 시도 3번은 고친 뒤에도 시작으로 잡히지 않았다 | [Voice Interface](../conversation/voice.md#실제-전사-기록에서-focus-키워드-해석) |
| 영어 답의 첫 소리 | 조각마다 받기 1.2~2.2초, 한 번에 합성 2.6~7.8초 | [Voice Interface](../conversation/voice.md#jarvis-답의-첫-소리까지-한-번에-문장마다-조각마다) |

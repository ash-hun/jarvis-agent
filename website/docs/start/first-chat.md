# 첫 대화

이 페이지는 jarvis-agent 를 띄운 직후 5분 안에 핵심 동작 세 가지를 직접 보는 길이다. 내적 사고(💭), 승인, 먼저 건네는 말(🔔)을 차례로 확인한다. 아직 띄우지 않았다면 [설치와 실행](./install.md)부터 한다.

## 사고 한 줄 보기

"안녕" 한 마디를 보낸다. 응답 위에 💭 로 시작하는 한 줄이 뜨면 [내적 사고](../concepts/inner-thought.md)가 켜진 것이다. 이 한 줄은 JARVIS 가 답하기 전에 따로 내린 판단의 요약이다.

## 승인 해 보기

셸을 써야 하는 요청을 보낸다. 예를 들면 "지금 폴더에 무슨 파일이 있어?" 다. 승인 모달이 뜨면 다음 셋 중 하나를 누른다.

- `ALLOW`: 이번 한 번만 허용한다. Enter 도 같다
- `ALWAYS`: 서버가 제안한 명령 패턴을 기억하고 다음부터 묻지 않는다. 서버가 패턴을 제안했을 때만 보인다
- `DENY`: 실행하지 않는다

120초 동안 답하지 않으면 거부로 처리한다.

:::danger
`ALWAYS` 는 지금 세션 에이전트의 승인 규칙 파일(`~/.jarvis/approvals/<agent_id>.yaml`)에 패턴을 남긴다. 지우거나 덮어쓰는 명령에 `ALWAYS` 를 누르면 그 뒤로는 묻지 않고 실행한다. 규칙을 되돌리려면 그 파일에서 해당 줄을 지운다.
:::

승인 규칙이 어떻게 쌓이고 나뉘는지는 [도구와 승인](../concepts/tools-and-approval.md)에 있다.

## 먼저 건네는 말 기다리기

대화를 멈추고 2분쯤 둔다. JARVIS 가 성찰한 끝에 할 말이 분명하다고 판단하면 🔔 로 먼저 말을 건다. 할 말이 없으면 침묵하는 게 정상이다.

🔔 가 오지 않을 때는 백엔드 로그에서 `[Thought] proactive silent: <이유>` 를 찾는다. JARVIS 는 침묵할 때마다 이유를 이 줄에 남긴다. 이유별 대처는 [문제 해결](../troubleshooting.md)에 있다.

# Proactive Jarvis — Web UI Voice 테스트 시나리오

> 대상: 누적 구현된 proactive 스택(Tier 0~3)을 **Web HUD 음성 인터페이스** 기준으로 수동 검증.
> 관련: [proactive-implementation.md](proactive-implementation.md)

## 0. 사전 준비

### 0.1 스택 기동 (daemon을 짧은 주기로 — 자율 발화를 빨리 보기 위함)

```bash
JARVIS_SESSION__POSTGRES_DSN=postgresql://jarvis:jarvis@postgres:5432/jarvis \
JARVIS_PROACTIVE__DAEMON_ENABLED=true \
JARVIS_PROACTIVE__DAEMON_INTERVAL_SEC=60 \
JARVIS_PROACTIVE__DAEMON_TRIGGER=both \
JARVIS_PROACTIVE__COOLDOWN_SEC=30 \
docker compose --profile web up -d
```

### 0.2 환경

| 항목 | 값 |
|------|-----|
| 브라우저 | Chrome 또는 Edge (Web Speech API 필요) |
| 접속 | http://localhost:7777 |
| 음성 모드 | STT=browser / TTS=browser (Web Speech, 한국어 `ko-KR`) |
| 마이크 | 권한 허용 필요 (첫 클릭 시 브라우저가 요청) |
| LLM | anthropic / claude-sonnet-4-5 (실 API — 과금 발생) |

### 0.3 음성 조작

- **구체(sphere) 클릭** → 음성 모드 토글. 클릭 후 말하기 → 인식되면 자동 전송.
- 음성으로 시작한 요청은 응답·filler·proactive 발화가 **TTS로 재생**된다.
- 💭 사고 라인은 **화면에만** 뜨고 음성으로는 나오지 않는다(의도된 분리).

> ⚠️ 발화 절제: proactive는 confidence 임계치+쿨다운+silent 편향으로 **자주 침묵**한다. "🔔이 안 떴다"가 곧 버그는 아니다 — 각 시나리오의 "침묵도 정상" 주석 참고.

---

## 시나리오 1 — 음성 왕복 기본 (STT→응답→TTS)

**목적:** 음성 입력 → 응답 → 음성 출력 기본 경로.

1. 구체 클릭(음성 모드 ON, 구체가 listening 상태).
2. "안녕, 너 뭐 할 수 있어?" 라고 말한다.
3. 인식된 텍스트가 `USER`로 채팅에 표시되고 자동 전송.
4. Jarvis 응답이 스트리밍으로 표시.
5. 응답 완료 후 **TTS로 응답을 읽어준다**.

**기대:** STT 전사 정확, 응답 스트리밍, 응답 TTS 재생. 구체 상태가 listening→processing→speaking→idle로 전이.

---

## 시나리오 2 — Inner Thought 가시화 (사고는 화면만, 음성 X)

**목적:** 매 요청 시 💭 사고 라인이 뜨고, 음성으로는 새어나오지 않음.

1. 음성으로 "어제 배포가 좀 불안했는데 상태 어때?" 라고 말한다.
2. 응답 위/앞에 **💭 시안색 흐릿한 사고 라인**(해석 + decision · 신뢰도%)이 뜨는지 확인.
3. TTS는 **메인 응답만** 읽고 💭 내용은 읽지 않는지 확인.

**기대:** 💭 라인 표시 O / 💭 TTS 발화 X. 사고가 의도를 해석(불안 감지 등)했는지 내용 확인.

---

## 시나리오 3 — Dual-Channel filler (오래 걸릴 작업 → 즉시 "잠깐만요" 발화)

**목적:** 시간이 걸리는 요청에 filler를 먼저 음성으로 내보내고 본 작업은 백그라운드.

1. 음성으로 도구가 필요한 요청을 한다. 예: **"이 프로젝트에서 web 관련 파일들 찾아서 요약해줘."**
2. 응답이 길어질 것으로 판단되면(💭 `needs_background`), 먼저 **💬 filler**("잠깐만요, 확인하고 알려드릴게요" 류)가 뜨고 **즉시 TTS로 재생**.
3. 이어서 실제 작업이 진행되고(도구 실행 표시), 완료되면 본 응답이 표시·발화.

**기대:** filler가 본 응답보다 **먼저** 음성으로 나온다(대기 체감↓). filler는 "시간이 걸린다"는 뜻을 담는다.
**침묵도 정상:** 모델이 즉답 가능하다고 판단하면 filler 없이 바로 응답(이 경우 needs_background=false).

---

## 시나리오 4 — Open-loop 추적 (약속 → 추적 → 상기)

**목적:** 대화에서 흘린 약속을 감지·저장하고 이후 떠올림.

1. 음성으로 **"내일 배포 끝나면 결과 공유하기로 한 거 기억해둬."** 라고 말한다.
2. 응답 후, 채팅 입력창에 `/openloop` 입력(텍스트) → **"내일 배포 결과 공유"류 항목이 목록에 표시**되는지 확인.
3. (선택) daemon 주기가 지나면, 맥락상 상기할 가치가 있을 때 🔔로 먼저 언급될 수 있다.
4. 완료 처리: `/openloop done <id 앞 8자>` → 해당 항목이 닫힘.

**기대:** open-loop가 감지·저장되고 `/openloop`에 표시. done 처리 시 목록에서 사라짐.
**침묵도 정상:** 같은 약속을 또 말해도 중복 저장되지 않는다(dedup).

---

## 시나리오 5 — Proactivity Daemon 자율 발화 (요청 없이 먼저 말 검)

**목적:** 요청이 없어도 daemon이 성찰해 먼저 🔔로 말 검 (voice 모드면 TTS).

1. 시나리오 2~4로 **대화 맥락을 어느 정도 쌓는다**(빈 세션에선 성찰할 게 없어 대부분 silent).
2. 음성 모드를 켠 채로 **약 1~2분간 입력하지 않고 기다린다**(idle).
3. daemon 틱(설정 60초)마다 성찰 → 게이팅 통과 시 **🔔 먼저 건넨 말**이 뜨고 **TTS로 재생**.
4. 발화에 👍/👎 피드백 버튼이 함께 표시되는지 확인.

**기대:** idle 시점에 맥락상 도울 가치가 분명하면 🔔 발화(+TTS). open-loop가 있으면 상기, 저위험 작업은 "(미리 해둠) …" 요약 동반 가능.
**침묵도 정상:** 확신이 부족하면 silent로 기운다. 쿨다운(30초) 내 반복 발화는 억제된다. 여러 틱 동안 아무 말 없을 수 있음 — 정상.

---

## 시나리오 6 — 피드백 학습 (버튼 + 음성 키워드)

**목적:** proactive 발화 수락/무시를 기록해 발화 임계치를 조정.

**6-A 버튼:**
1. 시나리오 5에서 🔔 발화가 뜨면 **👎 무시** 버튼 클릭.
2. 버튼이 비활성화(처리됨)되는지 확인.

**6-B 음성 키워드:**
1. 다른 🔔 발화가 뜬 직후, 음성 모드에서 **"무시"** 또는 **"좋아"** 라고 짧게 말한다.
2. 채팅에 "피드백: 무시 / 도움됨" 시스템 라인이 뜨고 일반 요청으로 전송되지 않는지 확인.

**기대:** 무시 누적 → 이후 daemon이 더 보수적으로(임계치↑) 침묵 쪽으로. 수락 누적 → 더 적극적으로.
**검증 팁:** 👎를 여러 번 주면 이후 🔔 빈도가 줄어드는 경향(즉각적이진 않음 — 단조 조정).

---

## 시나리오 7 — 장기 인지 (User Model / 저널)

**목적:** 누적 기억 증류 + 자기 성찰이 사고에 반영.

1. 몇 차례 대화로 선호를 드러낸다(예: "답변은 짧게 해줘", "Python 위주야").
2. `/usermodel build` → 사용자 모델이 생성·표시(요약 + traits)되는지 확인.
3. `/usermodel` → 저장된 모델 재확인.
4. `/journal write` → 최근 사고를 메타 성찰한 저널 항목 생성.
5. 이후 요청의 💭 사고가 사용자 모델을 반영하는지(예: 간결함 선호 인지) 정성 확인.

**기대:** `/usermodel`에 선호/패턴이 잡히고, `/journal`에 자기 성찰 기록이 쌓인다.

---

## 시나리오 8 — 비-voice 회귀 (텍스트 입력은 그대로)

**목적:** 음성 기능이 텍스트 경로를 깨지 않음.

1. 음성 모드 OFF 상태에서 텍스트로 동일 요청.
2. 💭/응답/filler(화면)·🔔은 동일하게 동작하되 **TTS는 재생되지 않음**.

**기대:** 텍스트 모드에서도 proactive 동작은 동일, 음성 출력만 없음.

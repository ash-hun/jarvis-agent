# Jarvis Web HUD 화면기능 명세

| 항목 | 값 |
|---|---|
| Last Updated | 2026-11-03 |
| 소스 | `src/jarvis/ui/web/static/` (`index.html`, `styles.css`, `app/*.js`, `hud.js`, `sphere.js`, `voice.js`, `wake-worklet.js`, `sw.js`), 데스크톱 셸 `desktop/` |

## 화면 목록

경로 알파벳순.

| 경로 | 화면 | 목적 | 상태 |
|---|---|---|---|
| `/` | HUD | 에이전트와 대화하고 옆 카드로 상태를 본다 | 구현됨 |
| `/` (FLOW) | Workflow | 에이전트 사이 위임과 백그라운드 작업을 본다 | 구현됨 |
| `/` (SET) | Settings | 설정을 보고 허용 목록 안의 값을 고친다. 데스크톱 앱이면 앱 설정도 | 구현됨 |
| `desktop/loading.html` | 연결 중 | 데스크톱 앱이 백엔드를 확인하거나 띄우는 동안, 실패하면 이유 | 구현됨 |

경로는 하나고, 화면 셋(HUD, FLOW, SET)은 헤더 오른쪽 탭으로 바꾼다(`body[data-view]`, 고른 화면은 localStorage `hud.view`). 바꿀 때 지금 화면의 카드가 반대쪽으로 살짝 물러났다가 화면 밖으로 빠지고(HUD 는 왼쪽 열은 왼쪽, 오른쪽 열은 오른쪽, 리액터는 안으로 접힌다), 다음 화면의 카드가 반대편에서 차례로(45ms 간격) 밀려 들어와 조금 지나쳤다가 두 번에 걸쳐 제자리에 걸린다(나가기 240ms, 들어오기 420ms). 탭 밑줄 하나가 고른 탭으로 미끄러져 간다. 움직이는 동안 누른 탭은 마지막 것 하나만 끝난 뒤에 간다. 움직임 줄이기 설정이면 바로 바뀌고, 처음 열 때는 움직이지 않는다. 세션 전환은 URL 이 아니라 WebSocket 재연결로 한다. 그 외 경로는 nginx 가 `index.html` 로 돌려준다.

## 화면별 상세

### `/` HUD

**목적**: 가운데 리액터를 중심으로, 왼쪽에 에이전트 상태 카드, 오른쪽에 세션과 대화를 둔다. 접속하면 바로 `default` 세션(JARVIS)에 붙는다. 화면의 이름, 명언, 색(링, 구체, CSS 변수)은 지금 세션 에이전트의 것이다.

**레이아웃**: 헤더, 3열 스테이지, 하단 입력 독.

```
┌──────────────────────────────────────────────────────────────┐
│ [≡]              ● J.A.R.V.I.S.               HUD  FLOW  SET  │ 헤더
│                  2026.11.03 TUE 13:14:57                     │
├───────────────┬──────────────────────────┬───────────────────┤
│ AGENDA        │                          │ SESSIONS        + │
│  UPCOMING     │    ‹   리액터(구체)   ›   │  default  NOW ⑂   │
│  OPEN LOOPS   │                          │                   │
├───────────────┤       ● ACTIVE           ├───────────────────┤
│ ACTIVITY      │       "명언" / 마지막 줄  │ CONVERSATION      │
│               │                          │  USER / J.A.R.V.I.S│
│               │                          │  💭  SYS          │
├───────────────┴──────────────────────────┴───────────────────┤
│ >_ [입력창                              ]  [SEND ⏎]          │ 입력 독
└──────────────────────────────────────────────────────────────┘
```

헤더 가운데 묶음(연결 점, 이름, 그 밑의 날짜와 요일과 시각)은 창 가운데가 아니라 리액터 구체의 가로 중심에 맞춘다(`header.js`). 좌우 카드 열 폭이 달라 둘이 어긋나기 때문이다. 연결 점은 이름 왼쪽에 띄워 두어 이름 글자만으로 가운데를 맞춘다. 오른쪽은 화면 탭(밑줄)이고, 왼쪽 ≡ 버튼은 860px 이하에서만 보인다. 헤더에 상태 글(READY 등), 버전, 음성 모드 버튼은 없다. 지금 무엇을 하는지는 리액터 아래 상태 줄이 보인다.

헤더 바로 아래 ION 띠는 플랫폼 감시(Ion)가 연 사고가 있을 때만 나타난다(붉은 기운의 한 줄, `ION` 표식). 사고마다 제목, 상세, 버튼(첫 버튼이 추천, 붉은 테두리)이 한 줄이고, 답하면 버튼 대신 `재기동 · 재기동함` 같은 결과가 8초 보였다가 사라진다. 이 띠는 `/ion/` 로 Ion 컨테이너에 붙어 백엔드 ws 가 끊겨도 산다. 열린 사고가 있는 동안 리액터 구체 뒤 배경이 가장 심한 등급의 색으로 물든다(critical 은 붉은색, warning 은 주황색. `body[data-ion]`). 사고는 띠와 함께 지금 보고 있는 대화(어느 에이전트의 세션이든)에 `ION` 카드로 끼어든다. 카드는 띠와 같은 줄(제목, 상세, 버튼)이고 답하면 결과가, 신호가 사라지면 `해결됨` 이 남는다. 세션을 바꾸면 열린 사고 카드가 새 대화에 다시 끼어든다. 카드는 화면에만 있고 저장되지 않는다.

열 안은 세로 flex 다. 카드를 접으면 아래 카드가 그 자리를 채운다. ACTIVITY 는 최소 96px 를 지킨다. 860px 이하에서는 왼쪽 열이 드로어가 되고(헤더의 ≡ 버튼), 리액터 아래에 SESSIONS 와 CONVERSATION 이 온다.

**Focus 레이아웃** (`body[data-focus="on"]`, `/focus <작업>` 동안):

```
┌──────────────────────────────────────────────────────────────┐
│                  ● J.A.R.V.I.S. [FOCUS]         HUD FLOW SET  │
├─┬──────────────────────┬───────────┬───────────────────────┬─┤
│A│ REFERENCE  조사 및 종합│  ╭─────╮  │ ANALYSIS 목적, 필요…   │S│
│G│  선례, 출처, 적용할 점 │ (  구체  ) │  근본 목적 … 미리 대비 │E│
│E│                      │  ╰─────╯  │                       │S│
│N├──────────────────────┤  ● ACTIVE ├───────────────────────┼─┤
│D│ LOG  작업 기록         │           │ PROGRESS        경과   │C│
│A│  시각별 3인칭 기록     │           │  33%       약 21분 남음│O│
│…│                      │           │  ✓ 단계 ○ 단계         │N│
├─┴──────────────────────┴───────────┴───────────────────────┴─┤
│ >_ [입력창                              ]  [SEND ⏎]          │
└──────────────────────────────────────────────────────────────┘
```

좌우 카드는 머리글만 세로로 세운 30px 띠가 된다. 구체는 70% 크기에 채도와 밝기가 오르고, 둘레에 네 영역 쪽으로 뻗는 호가 그려진다. 들어갈 때는 띠 접힘, 구체 축소, 호, 네 영역 순으로 약 1.2초, 나올 때는 거꾸로 간다. 아래 줄(LOG, PROGRESS)은 내용 높이만큼(최소 30%, 최대 50%)이고 남는 높이는 위 줄이 갖는다. LOG 바닥에 `기록 N건 · 마지막 HH:MM`, PROGRESS 바닥에 `단계 완료/전체 · 갱신 HH:MM` 한 줄이 붙는다. 구체 아래 캡션은 가운데 빈 칸(구체 폭의 절반) 안의 한 줄로 줄고, 마크다운 기호와 반쯤 온 링크를 걷어 낸 글자만 보인다. 응답이 나오는 동안 CONVERSATION 띠가 숨쉬듯 빛난다(펼쳐 두면 빛나지 않는다). 860px 이하에서는 구체 아래로 PROGRESS, REFERENCE, ANALYSIS, LOG 를 쌓고 맨 아래에 CONVERSATION 막대만 둔다.

**상태와 파라미터**

| 이름 | 위치 | 기본값 | 효과 |
|---|---|---|---|
| `session_id` | WS 쿼리 | `default` | 어느 세션에 붙는지. 화면 안에서만 바뀐다 |
| 함께 일하는 에이전트 | `agent_activity.active` | 빈 목록 | 둘 이상이면 구체 입자가 그 에이전트들의 primary 두 색으로 흐르는 띠처럼 섞인다(지금 에이전트 색이 먼저, 약 1초에 걸쳐 섞이고 끝나면 같은 속도로 돌아온다). 일하는 에이전트 칩은 숨쉬듯 빛난다 |
| 세션 에이전트 | `connected.agent`, `html[data-agent]` | `main` | 이름, 명언, 색. 바뀌면 약 0.9초에 걸쳐 새 색으로 섞인다. CSS 색 변수(`@property` 로 등록해 transition), 링과 별(hud.js, 별은 자리를 지킨 채 색만), 구체와 원판(sphere.js)이 함께 바뀐다. 움직임 줄이기 설정이면 바로 바뀐다. 새로고침하면 `default`(JARVIS)로 돌아간다 |
| `jarvis_token` | localStorage | 없음 | 접근 키. `4401` 로 끊기면 `prompt()` 로 묻고 저장 |
| `hud.chatCollapsed` | localStorage | `0` | CONVERSATION 접힘 |
| `hud.sessionsCollapsed` | localStorage | `0` | SESSIONS 접힘 |
| 연결 | `body[data-link]` | `offline` | 세션이 붙으면(`connected`) `online`, 소켓이 끊기면 `offline`. 헤더 이름 옆 점이 online 이면 파랗게 깜빡이고 offline 이면 빨갛게 멈춘다. 끊기면 헤더 바로 밑에 재연결 배너도 뜬다 |

**빈 상태**

CONVERSATION: 히스토리가 없으면 `— SESSION · 시각 · id —` 한 줄만. AGENDA: `예정된 작업 없음`, `남은 할 일 없음`(CSS `data-empty`), 닫힌 약속이 없으면 Closed 줄을 숨긴다. TOOLS: 0. ACTIVITY: 접속 줄 하나. 리액터 캡션: 명언. Focus: REFERENCE `조사 중인 레퍼런스가 없습니다`, ANALYSIS `지시를 분석하는 중입니다`, LOG `아직 기록이 없습니다`, PROGRESS 단계 목록 `단계를 나누는 중입니다`, 예상 시간 `예상 시간 계산 중`. SESSIONS 의 에이전트 칩: 에이전트가 하나면 숨긴다.

**에러 상태**

WS 끊김: 헤더 이름 옆 점이 빨갛게 멈추고, 헤더 바로 밑에 배너 `연결 끊김 — 재연결 중...`, 입력 잠금, 1초부터 2배씩 최대 10초 간격으로 재접속. `4401`: 키 입력 `prompt()`, 취소하면 배너와 ACTIVITY `접근 키 없음`. `agent_error`, `error`: SYS 에러 메시지 + 리액터 상태 `error` 3초 뒤 대기. `/api/agenda`, `/api/tools` 실패: 콘솔 경고만, 화면은 이전 값 유지. 히스토리 실패: 응답이 실패 코드면 아무 표시 없이, 요청이 예외면 콘솔 에러. 대화는 빈 채로 둔다. `/api/agents` 실패: 빈 목록으로 둔다(칩과 에이전트 라벨 없음). 응답이 실패 코드(401 등)면 새로고침 전까지 다시 받지 않고, 네트워크 오류면 다음 호출 때 다시 받는다. `/api/voice/phrases/{name}` 실패: 담아 두지 않고 합성으로 읽는다. ⑂ 분기 실패: 처리 없음. open loop 처리 실패: ACTIVITY `open loop 처리 실패`, `open loop 되살리기 실패`. 스케줄 변경 실패: ACTIVITY `스케줄 변경 실패 · <name>`. STT 오류: SYS `STT 오류: …`, 인식한 글이 비면 SYS `음성을 인식하지 못했습니다.`. `4404`(모르는 에이전트): 재접속하지 않는다. ACTIVITY `에이전트 없음 · <세션> · <이유>` 를 남기고, 보던 세션이 `default` 가 아니면 `default` 로 한 번 옮겨 붙는다. `default` 도 4404 면 배너만 남기고 멈춘다. 승인 요청 120초 무응답: 서버가 거부로 처리하고 도구 결과에 `denied` 가 온다. 음성 TTS 오류: `error` 로 와서 음성 상태가 풀린다.

### `/` FLOW — Workflow

**목적**: 어느 에이전트가 누구에게 일을 맡겼는지(관계 그래프와 최근 위임)와, 대화 밖에서 도는 작업이 언제 돌았고 어떻게 끝났는지를 한 화면에서 본다.

**레이아웃**: 헤더와 입력 독은 HUD 와 같다. 스테이지 자리에 카드 셋.

```
┌──────────────────────────────────────────────────────────────┐
│ 헤더 [HUD|FLOW|SET]                                           │
├──────────────────────────────────────┬───────────────────────┤
│ AGENT KNOWLEDGE GRAPH  고유 N · 공통 M │ DELEGATIONS         N │
│ write_file○╲        ∙ask_agent  ╱●housing_budget│ JARVIS → KAREN 질문 │
│ edit_file ○─(J)╌╌╌╌ ∙glob ╌╌╌╌(K)─●lh_notice    │  AI 뉴스 3개 찾아 줘│
│ bash      ○╱        ∙web_search ╲●sh_notice     │  01:51:47 · 5.0s    │
│ ● 고유 ∙ 공통 ○ 승인 필요 ╌ sub ╌ 진행 중 ─ 실패  │                     │
├──────────────────────────────────────┴───────────────────────┤
│ BACKGROUND JOBS                                 성찰 interval · 120s │
│ 작업        상태    실행  마지막     다음                        │
│ 아침 브리핑  성공    3     09:00:04   내일 09:00                  │
├──────────────────────────────────────────────────────────────┤
│ >_ [입력창                              ]  [SEND ⏎]          │
└──────────────────────────────────────────────────────────────┘
```

860px 이하에서는 AGENT GRAPH, DELEGATIONS, BACKGROUND JOBS 를 한 열로 쌓는다.

**데이터**

| 영역 | 원천 | 갱신 |
|---|---|---|
| 그래프 노드 | `GET /api/workflow` 의 `agents` 를 가로 한 줄 허브로(에이전트 색 원, 이름, `고유 N`). `capabilities` 중 한 에이전트만 가진 도구와 그 에이전트가 위임하는 `subagents`, 간선에만 나온 받는 쪽(점선 원)은 그 허브 바깥쪽으로 부채꼴 잎. 여럿이 함께 쓰는 도구는 주인 허브들 사이에 세로로 쌓고 주인마다 흐린 점선으로 잇는다(자리가 모자라면 두 줄). 승인이 필요한 도구는 속이 빈 주황 원. 이름은 18자에서 자르고 `procedure_` 를 뗀다 | 화면을 열 때마다 다시 받는다 |
| 그래프 간선 | `edges` 를 (부른 쪽, 받는 쪽) 쌍마다 하나로. 선 위에 `×횟수` | ws `workflow_changed` 마다 한 건 더하고 한 프레임에 한 번 다시 그린다 |
| DELEGATIONS | 최근 40건, 최신이 위. 경로, 종류(질문, sub-agent, orchestrate, focus), 맡긴 일, 시작 시각과 걸린 시간 | 같은 이벤트 |
| BACKGROUND JOBS | `GET /api/jobs`. 스케줄이 먼저, 그 뒤 성찰, 기억 정리, 외부 조회 | ws `job_changed` |

**상태와 파라미터**

| 표시 | 뜻 |
|---|---|
| 흐르는 노란 점선 간선, 노드 안 채움 | 그 쌍에 끝나지 않은 위임이 있다 |
| 빨간 간선 | 그 쌍의 마지막으로 끝난 위임이 실패했다 |
| 상태 `실행 중` / `성공` / `실패` / `꺼짐` / `대기` | 작업이 지금 도는 중 / 마지막 실행 성공 / 실패(이름에 마우스를 올리면 이유) / 꺼진 스케줄 / 아직 돈 적 없음 |
| 헤더 오른쪽 `성찰 <trigger> · <interval>s` | daemon 설정. 꺼져 있으면 `성찰 꺼짐` |

**인터랙션**: 보기만 한다. 에이전트 허브에 마우스를 올리면 그 에이전트에 닿은 잎, 공통 능력, 간선만 밝게 남고 나머지는 흐려진다. 잎에 올리면 도구 이름 전체, 승인 필요 여부, 설명. 간선에 올리면 `이름 → 이름 · N회`. `Esc` 는 HUD 로 돌아간다(입력 중이 아닐 때).

**빈 상태**: 위임이 없으면 그래프에 에이전트 노드만, DELEGATIONS 는 `이 프로세스가 본 위임이 아직 없습니다`. 작업이 없으면 표 대신 `등록된 백그라운드 작업이 없습니다`.

**에러 상태**: REST 실패는 이전 값을 그대로 두고 다음에 화면을 열 때 다시 받는다. 서버가 재시작되면 그래프와 실행 횟수가 비어 다시 쌓인다.

### `/` SET — Settings

**목적**: 지금 적용된 설정을 보고, 화면에서 고쳐도 안전한 값(voice, proactive, thought, focus 의 일부)을 저장한다. 데스크톱 앱이면 단축키와 자동 실행 같은 앱 설정도 여기서 고친다.

**레이아웃**: 왼쪽 열에 SYSTEM 과 DESKTOP(데스크톱 앱에서만), 오른쪽 열(2배 폭)에 SETTINGS, 아래 줄 전체에 EFFECTIVE CONFIG. 860px 이하에서는 한 열로 SYSTEM, SETTINGS, DESKTOP, EFFECTIVE CONFIG 순. SYSTEM 은 HUD 왼쪽 열에 있던 카드를 그대로 옮긴 것이다(가동 시간, 모델, 세션, 토큰, 비용, 사용량 그래프, TOOLS 목록).

```
┌──────────────────────────────────────────────────────────────┐
│ 헤더                                          HUD  FLOW  SET  │
├────────────────────┬─────────────────────────────────────────┤
│ SYSTEM    00:12:04 │ SETTINGS        ~/.jarvis/settings.yaml │
│  MODEL   gpt-4o    │ VOICE                                   │
│  TOKENS…COST       │  Stt Provider    [browser ▾]            │
│  TOOLS ▾           │  Wake Threshold  [0.5     ]             │
├────────────────────┤ PROACTIVE …                             │
│ DESKTOP    앱 전용 │                                         │
│ 전역 단축키 [ … ]   │ 저장됨 · 재시작하면 반영 [RESTART] [SAVE] │
│ 백엔드 주소 [ … ]   │                                         │
├────────────────────┴─────────────────────────────────────────┤
│ EFFECTIVE CONFIG                                  비밀값 ***  │
│ { "llm": { "provider": "anthropic", "api_key": "***", … } }   │
└──────────────────────────────────────────────────────────────┘
```

**데이터**: 폼은 `GET /api/settings` 의 `fields`(형식, 선택지, 범위)로 그리고 값은 `pending` 이 있으면 그 값, 없으면 `editable`. 선택지가 있으면 select, boolean 은 체크박스, 숫자는 범위가 걸린 number, 문자열은 pattern 이 걸린 text. DESKTOP 은 `window.jarvisDesktop.getSettings()`.

**상태와 파라미터**: `pending` 에 든 행은 이름 뒤에 `· 재시작 대기`. 대기 항목이 있으면 상태 줄 `저장됨 · 백엔드를 다시 띄우면 반영됩니다`, 데스크톱 앱에서는 RESTART BACKEND 버튼이 보인다.

**인터랙션**: SAVE 는 적용값과 다른 값만 `PUT /api/settings` 로 보낸다. 바뀐 것이 없으면 `바뀐 값이 없습니다`. RESTART BACKEND 는 셸이 `docker compose restart jarvis-backend` 를 돌리고 백엔드가 응답하면 페이지를 다시 읽는다. DESKTOP 의 SAVE 는 셸이 검증해 저장하고 단축키와 자동 실행을 바로 적용한다.

**빈 상태**: 브라우저에서는 DESKTOP 카드와 RESTART BACKEND 가 없다. 브라우저에서 반영하려면 `docker compose restart jarvis-backend` 를 직접 실행한다.

**에러 상태**: 형식이나 범위가 틀린 칸이 있으면 저장하지 않고 `범위나 형식이 맞지 않는 값이 있습니다` 와 함께 그 칸으로 간다. 서버 422 나 실패 코드는 `저장 실패 (코드)`, 연결이 없으면 `백엔드에 연결되지 않았습니다`. 데스크톱 설정이 틀리면(루프백이 아닌 주소, 등록할 수 없는 단축키) 셸이 거절한 이유를 보인다. 재시작이 실패하면 `재시작 실패: <이유>`.

## 미구현 / 알려진 제약

- 음성 승인 답은 부정어가 있으면 분류 없이 거부한다. "허용 안 해" 처럼 긍정과 부정이 섞인 말은 늘 거부다.
- 웨이크워드가 켜져 있으면 대기 중에도 마이크를 계속 열어 두므로 녹음 표시가 꺼지지 않는다. 마이크를 닫으려면 `JARVIS_VOICE__WAKE_MODEL_DIR` 를 비운다.
- 음성 대화의 자동 듣기는 읽기가 끝날 때마다 한 번이다. 말이 없으면 대화가 끝나고, 다시 시작하려면 "Jarvis" 라고 부르거나(웨이크워드가 켜져 있을 때) 구체를 누른다.
- 웨이크워드는 Chrome 처럼 16kHz AudioContext 에 마이크를 바로 이을 수 있는 브라우저에서만 돈다. 안 되면 ACTIVITY 에 `wake word off · <이유>` 를 남기고 끈다.
- 웨이크워드 모델은 합성 음성으로만 학습했다. "Jars", "Garbage" 처럼 비슷한 소리에 깨어날 수 있고, 한국어 발음 "자비스" 는 알아듣지 못한다.
- 읽기 문구는 다른 읽기와 겹칠 수 있다(도구 시작 문구를 읽는 중에 💬 filler 문구가 오면 둘 다 소리 난다).
- 읽기가 겹치면(💬 filler 를 읽는 중에 승인 요청이 오면) 소리가 겹치고, 먼저 끝난 쪽에서 듣기가 시작될 수 있다.
- Focus 동안 🔔(먼저 건네는 말)는 서버가 보내지 않는다. 💬 filler 와 맡긴 일의 답은 그대로 온다.
- Focus 의 진행률은 진행 sub-agent 가 매긴 단계 완료로 계산한다. 단계를 늘리면 퍼센트가 내려간다. 예상 시간은 지금까지 걸린 시간 / 완료 단계 수 × 남은 단계 수라, 완료 단계가 없으면 `예상 시간 계산 중` 이다.
- Focus 의 분석은 지시가 들어올 때 메인 응답과 같이 돈다. 그 결과는 이번 응답이 아니라 다음 응답의 시스템 프롬프트에 들어간다(첫 지시만 시작할 때 기다려서 첫 응답에 넣는다).
- 세션 목록은 프로세스가 띄운 것만 보인다. 저장소에만 있는 세션은 화면에 없다.
- Postgres 저장소에서 ⑂ 분기는 빈 새 세션이다. 히스토리가 복사되지 않는다.
- open loop 중복 판정은 정규화 일치, 포함 관계(6자 이상), 임베딩 코사인 0.85 이상(`JARVIS_MEMORY__EMBEDDING_*` 설정이 있을 때), 글자 bigram 겹침(Jaccard 0.4 이상)이다. 뜻이 멀게 바꾼 약속("운동 등록" 과 "헬스장 회원권")은 따로 쌓인다.
- open loop 는 ✓ / ✕ 말고도, 대화에서 끝났거나 취소됐다고 AGENDA 판단이 판단하면 done 으로, 사용자가 취소하는 말로 가리키면 dismissed 로, 기한이 지나면 expired 로 저절로 닫혀 Open loops 에서 빠진다. 잘못 닫힌 것은 Closed 에서 ↺ 로 되살린다. Closed 는 최근 10개만 보인다.
- 사용자 입력과 글자가 거의 겹치지 않는 새 약속은 저장하지 않는다. 입력과 전혀 다른 말로 바꿔 적은 약속은 AGENDA 에 오지 않는다.
- 구체 색 섞기는 두 색까지다. 세 에이전트가 함께 일해도 앞의 두 색만 섞인다. 링과 패널 색은 지금 에이전트 그대로다.
- 에이전트끼리의 대화(`peer-<부른 쪽>-<받는 쪽>` 세션)는 세션 목록에 다른 세션처럼 보인다. 눌러서 받는 쪽 대화를 볼 수 있다.
- AGENDA 는 모든 에이전트의 스케줄과 약속을 한 목록에 섞어 보여준다. 에이전트가 둘 이상일 때만 항목 시각 앞에 에이전트 이름 라벨(그 에이전트의 primary 색)이 붙는다. 에이전트별로 거르는 필터는 없다.
- open loop 는 닫기와 되살리기만 되고 수정은 없다. 스케줄은 켜고 끄기만 되고 만들기와 지우기는 슬래시 명령(`/schedule`)으로.
- 음성 TTS 요청에 서버가 응답하지 않으면 `음성 처리 중` 상태에 머문다(서버가 빈 `voice_tts_audio` 를 돌려주는 것으로 막고 있다).
- 오른쪽 아티팩트 패널은 응답 하나에 코드블록 하나만 보여준다(가장 긴 것).
- 입력창은 한 줄이다. 줄바꿈 입력 없음.
- Electron 의 브라우저 음성 인식은 Google 키가 없어 `network` 오류로 끝난다. 이때 서버 STT(`voice.stt_fallback`)가 있으면 그 연결이 끝날 때까지 녹음을 서버로 보내 받아 적고 ACTIVITY 에 `voice · 브라우저 인식 불가(network) → 서버 인식` 을 남긴다. 재접속하면 브라우저 인식부터 다시 시도한다.
- 데스크톱 앱에서는 Web Push(서비스 워커)가 돌지 않는다. 앱이 트레이에 떠 있는 동안만 OS 알림이 온다.
- Workflow 그래프는 원 두 개에 이름순으로 놓는다. 노드가 많으면 이름이 겹친다.
- router 를 켜면 direct 로 판정된 요청은 사고하지 않는다. 그 턴에는 💭 줄, 💬 filler 가 없다. think 로 판정된 요청의 사고는 응답과 함께 돌아 💭 줄이 응답 뒤에 오고, 그 해석은 이번 응답이 아니라 다음 응답에 쓰인다. 응답이 사고를 기다리지 않으므로 think 턴에도 💬 filler 는 나오지 않는다.
